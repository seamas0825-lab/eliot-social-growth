# Product-led Social

Use this reference when product value can become a repeatable, privacy-safe social artifact. The goal is not to add a share button; it is to let real outcomes prove value and create a sustainable acquisition-and-learning loop.

## Outcome loop

```text
Audience problem
→ product use case
→ successful user outcome
→ privacy-safe shareable artifact
→ social proof
→ new-user activation
→ new outcome
```

Map each step and identify where the loop breaks.

## Research questions

- After which successful action does a user feel most competent, relieved, proud, surprised, or understood?
- Can the product generate a useful artifact: result, before/after, workflow record, template, replay, audit trail, or summary?
- Does the artifact prove product value without a long brand explanation?
- Which personal, customer, company, or sensitive information must be hidden by default?
- Can a user edit, approve, anonymize, watermark, or revoke the artifact?
- Why would the user share: identity, utility, generosity, status, accountability, collaboration, or portfolio value?
- Why would the user allow brand amplification, and what consent is required?
- Can the content team turn outcomes into a searchable case library rather than isolated testimonials?
- Can recurring comments become product templates, demos, onboarding examples, experiments, or roadmap inputs?

## Artifact quality gate

A shareable artifact should be:

- generated from a real completed use case;
- understandable without misleading context;
- editable and user-controlled;
- private by default when exposure creates risk;
- specific enough to demonstrate value;
- attributable only when the user consents;
- accessible and platform-appropriate;
- measurable from share to qualified activation.

Reject forced sharing, dark patterns, automatic public exposure, fake outputs, cherry-picked outcomes without boundaries, and incentives that encourage spam.

## Operating system

Maintain stable IDs across:

- audience problem;
- product use case;
- activation and success event;
- artifact type;
- user consent state;
- social post or creator amplification;
- landing or onboarding path;
- downstream activation and retained outcome;
- product insight or template request.

Review monthly:

- which outcomes users voluntarily share;
- which artifacts drive qualified activation rather than curiosity;
- which use cases repeatedly fail or require manual help;
- which community questions should enter product education or product discovery;
- which claims need narrowing because social proof exceeds verified causality.

When the loop is not appropriate, use editorial content or customer research instead. Not every product outcome should become content.
